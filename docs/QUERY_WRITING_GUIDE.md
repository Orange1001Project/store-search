# 서비스셋 쿼리 직접 작성 가이드 (2026-10-19)

서비스형 쿼리셋 v1(`docs/SERVICE_QUERYSET.md`)의 **test에 들어갈 쿼리를 사람이 직접 쓰는 절차**다.
1부는 진행자용, 2부는 작성자에게 그대로 나눠 주는 안내문이다.

## 왜 다시 쓰나

`service_queryset_v1_completed.xlsx`는 500개 중 약 400개(80%)가 AI 초안을 사람이 검수한 쿼리다(A·C·D·E 전부). 사람이 직접 쓴 것은 B 150개뿐이다.
- AI 초안으로 test를 만들면 실제 사용자 분포가 아니라 **LLM이 쓰는 말투**를 재게 된다.
- 검수만 한 쿼리는 "사람이 쓴 쿼리"가 아니다. 검수자는 AI가 내놓은 표현 범위 안에서 고르기 때문이다.

**처리**
- AI 초안 약 350개(A·C·D·E)는 `ai_draft`로 표시해 dev 보조로만 쓴다. test에는 넣지 않는다.
- A·C·D·E 350개는 아래 절차로 사람이 새로 쓴다.
- B 150개는 사람이 쓴 것이므로 유지한다. 단, 지역표현과 가정위치를 채운다(4단계).

---

# 1부. 진행자 절차

## 1단계 — 작성자 모집 (3명, 2026-10-20 결정)

| 조건 | 이유 |
|---|---|
| 3명(1인 약 120줄, 두 번에 나눠 쓰기) | 원래 5명 이상을 권했다 — 한 사람의 말버릇이 셋 전체를 지배하지 않게. 3명이면 한 사람이 전체의 1/3이므로, 결과 보고에 작성자 3명이라는 한계를 적는다 |
| **가능하면 1명은 이 프로젝트 밖 사람**(다른 부서, 가족·지인도 가능) | 팀원은 업종 분류와 코퍼스 표현을 알아서 그 단어를 쓴다(기존 셋이 T1·T2에 쏠린 원인) |
| 연령대·생활 방식 섞기(20대·40대·60대, 자취·가족, 시장 자주 감·거의 안 감) | 온누리 사용자층은 넓다. 같은 상황도 세대마다 쓰는 말이 다르다 |
| AI 도구(ChatGPT 등)를 쓰지 않기로 동의 | 2부 금지 사항 |

작성자마다 ID(W1~W3)를 주고, `작성자정보` 시트에 연령대, 온누리상품권 사용 경험(자주/가끔/없음), 팀 내외부를 적는다.
이름은 적지 않는다. 결과를 작성자 특성별로 나눠 보는 데 쓴다.

## 2단계 — 배정

각자 다른 재료를 받되 C 카드는 세 명 모두 전부 받는다. 같은 상황을 세 사람이 쓰면 카드마다 서로 다른 첫 반응 3개를 얻는다.

| 묶음 | 전체 목표 | 1인 배정(3명) | 배정 방식 |
|---|---|---|---|
| C 상황 | 130 | 카드 45장, 카드당 1줄 | 세 명 모두 45장(45 × 3 = 135줄). 결이 다른 검색어가 또 떠오르면 줄을 추가해도 된다 |
| A 업종 | 150 | 업종 10개 × 5개 = 50 | `A_업종후보`에서 30개 업종을 골라 겹치지 않게 나눔 |
| D 지역+업종 | 50 | 17 | `D_시장표본`에서 서로 다른 시장(전체 51) |
| E 결과 없음 | 20 | 7 | 재료 없이 각자(전체 21) |
| 합계 | 350 | 약 120줄 · 3~4시간(1부·2부 두 번에 나눔) | |

**A 업종 30개 고르는 기준**: 쿼리셋에서 빠져 있던 업종을 고르게 넣는다.
- `미채택 업종` 15개 전부
- `기존 업종 보강` 14개 중 5개
- `미포함 품목` 중 가맹점 수가 많은 순으로 10개(예: 식육·양약·당구장). 같은 업종의 다른 표기는 하나로 친다.

**파일 만들기**: `python scripts/make_writer_sheets.py`를 실행하면 `data/query/writers/서비스셋_직접작성_v1_3명.xlsx` 한 파일이 생긴다(파일 이름은 설정의 `writers.single_file`). 작성자 수를 바꿔 다시 만들 때는 `--carry-over <이전 파일>`로 이미 쓴 답을 옮긴다.
배정 내용(작성자 ID, 카드 겹침 수, 업종 30개, 1인당 시장·E 개수)은 `configs/query/service_queryset_v1.yaml`의 `writers` 블록에서 정한다.
- 시트 구성: `안내_1부(C·E)`, `안내_2부(A·D)`, `배정표`, `작성자정보`, `합계`, 그리고 작성자마다 `W1_1부_C_E` / `W1_2부_A_D` …
- 1부 시트에는 배정 카드마다 한 줄이 있고 카드 문장이 `재료` 칸에 들어 있다. E 칸 7줄도 있다.
- 2부 시트에는 업종마다 5줄, 시장마다 1줄이 있다. 가정위치ID는 미리 채워 두었다.
- 작성자가 채울 칸(질의·의도·지역표현·비고)은 노란색이다.
- 작성자에게 나눠 줄 때는 그 사람의 안내·시트만 복사해 주거나, `--layout per-writer`로 작성자별 파일을 만든다.
  **한 파일을 공유해 여럿이 동시에 쓰면 서로의 쿼리가 보이므로 그렇게 하지 않는다.**
- 회수한 결과는 `data/query/writers_completed/`에 둔다.

**작성자마다 파일을 따로 준다.** 템플릿을 복사해 `service_queryset_v1_W1.xlsx`처럼 만들고, 그 사람에게 배정한 카드·업종·시장만 남긴다.
- AI 초안 파일(`*_completed.xlsx`)과 다른 작성자의 파일은 절대 주지 않는다.
- C 카드는 카드 시트만 먼저 주고, A·D 재료는 C를 끝낸 뒤에 준다(3단계 순서).

## 3단계 — 작성 진행 (작성자별, 한 번에 또는 2회로 나눠)

1. **15분 안내**: 2부를 같이 읽고 좋은 예·나쁜 예를 보여 준다. 질문은 이때만 받는다.
2. **C → E → A → D 순서로 쓴다.** 업종 목록이나 시장 목록을 먼저 보면 그 단어에 끌려가므로, 재료가 가장 적은 것부터 쓴다.
3. 묶음 사이에 진행자가 다음 재료를 연다. 이미 쓴 것은 고치지 않게 한다. 나중에 본 목록 때문에 고치게 되기 때문이다.
4. 끝나면 작성자가 2부의 "자기 점검"을 한다.

## 4단계 — 진행자 검수 (고치지 말고 표시만)

검수자가 쿼리를 고치면 그건 검수자의 쿼리가 된다. **문구는 바꾸지 않고** `검수` 열에 표시만 한다.

| 표시 | 기준 | 처리 |
|---|---|---|
| `중복` | 정규화(공백 제거·소문자)했을 때 다른 작성자와 같은 쿼리 | 하나만 남기고 `합의 수`에 몇 명이 썼는지 적는다(많이 겹치면 흔한 쿼리라는 신호) |
| `오타` | 맞춤법이 분명히 틀린 것(띄어쓰기 차이는 오타 아님) | 제외. 오타는 이 셋에서 다루지 않는다 |
| `범위밖` | 가게를 찾는 쿼리가 아님(질문 문장, 정보 검색). **E는 예외** | 제외 |
| `묶음 정정` | 묶음이 잘못 붙은 것(예: C에 지역명이 들어감 → D) | 묶음만 바꾼다 |
| (빈칸) | 문제없음 | 유지 |

**B 150개 보완**
- 질의에 지역이 들어 있으면("묵동 대박축산") 그 부분을 `지역표현`에 그대로 옮겨 적는다.
- `가정위치ID`는 비워 둔다. 가져오기 스크립트가 표본 가맹점 위치로 채운다.
- 질의 문구는 바꾸지 않는다.

**양 확인**: 묶음별로 목표의 90%에 못 미치면 같은 방식으로 추가 배정한다. 이때 이미 쓴 작성자보다 새 작성자를 우선한다.

## 5단계 — 넘기기

- 회수한 작성자 파일(한 파일 배치)을 `data/query/writers_completed/`에 둔다. AI 초안은 팀 작성본(`data/query/service_queryset_v1_team_completed.xlsx`)에 그대로 둔다.
- `python scripts/import_service_queries.py`로 가져온다. 중복 합치기, 제외, dev/test, 가정위치 규칙은 `docs/SERVICE_QUERYSET.md` 4절에 있다.
  dev/test는 작성자가 아니라 근거(업종·카드·가맹점·시장) 단위로 나눈다 — 같은 카드의 쿼리가 dev와 test에 갈라지지 않게.

# 2부. 작성자 안내문 (그대로 배포)

## 이 작업은

온누리상품권 앱·지도에서 **가맹점을 찾을 때 실제로 칠 검색어**를 모으는 일입니다. 정답이 있는 시험이 아닙니다.
**평소 휴대폰으로 검색할 때처럼** 쓰면 됩니다. 잘 쓰려고 다듬은 문장보다 대충 친 짧은 말이 더 쓸모 있습니다.

## 꼭 지켜 주세요

1. **ChatGPT 같은 AI, 검색 엔진, 지도 앱을 보지 마세요.** 머릿속에서 나온 말이어야 합니다.
2. **다른 작성자와 상의하지 마세요.** 끝날 때까지 서로의 쿼리를 보지 않습니다.
3. **오타를 일부러 넣지 마세요.** 띄어쓰기는 평소 습관대로 하면 됩니다(`떡볶이집`도 `떡볶이 집`도 괜찮음).
4. **한 번 쓴 것은 고치지 마세요.** 뒤에 받은 목록을 보고 앞의 것을 바꾸지 않습니다.
5. 길이: 대부분 2~10자, 길어도 20자 안쪽. 평소에 문장으로 검색한다면 문장도 괜찮습니다.

## 순서

C 상황 → E 결과 없음 → A 업종 → D 지역 순서로 씁니다. 다음 묶음의 재료는 앞 묶음을 끝내면 받습니다.

## 각 칸 쓰는 법

| 칸 | 내용 |
|---|---|
| 작성자 | 받은 ID (W1 등) |
| 묶음 | C / E / A / D |
| 질의 | 검색창에 칠 말 그대로 |
| 의도 | 쓰고 나서, **어떤 가게가 나오길 기대했는지** 짧게(예: 구두 수선집) |
| 지역표현 | D만. 질의 안의 지역 부분을 그대로 복사(예: `망원시장`) |
| 가정위치ID | D만. 고른 시장의 M번호 |
| 근거ID | 카드 C번호 / 업종 A번호 / 시장 M번호 |
| 작성방식 | `직접` |

### C — 상황 카드 (먼저)

카드 한 장을 읽고 **그 상황에 놓인 나**를 떠올립니다. 휴대폰을 꺼내 처음 치는 말 하나를 씁니다.

- 업종 이름이 떠오르면 그대로 써도 됩니다(`세탁소`). 실제로 그렇게 친다면 그게 맞는 답입니다.
- 물건, 하려는 일, 문제로 쳐도 됩니다(`패딩 세탁`, `이불 빨래`).
- 카드 문장을 그대로 옮기지는 마세요.

| 카드 | 좋은 예 | 피할 예 |
|---|---|---|
| 구두 뒤축이 다 닳았다 | 구두 굽 수선 / 구두 수선 | 구두 뒤축이 다 닳았을 때 가는 곳 (카드를 옮겨 적음) |
| 비 오는 날 저녁, 뜨끈한 국물이 당긴다 | 칼국수 / 국밥집 / 수제비 | 비 오는 날 국물 음식점 추천 (다듬은 문장) |
| 부모님 댁에 들고 갈 선물이 필요하다 | 과일 선물세트 / 홍삼 선물 | 부모님 선물 가게 (머릿속에서 나온 말이 아니라 상황 요약) |

### E — 결과가 없을 법한 검색

온누리 앱에서 누군가 쳐 볼 법하지만 **전통시장·상점가 가맹점은 아닐 것 같은 것**을 씁니다.

- 대형 업체(예: 이케아), 공공기관(예: 구청), 앱 기능(예: 상품권 잔액) 등
- 진행자가 나중에 실제 가맹점에 있는지 확인하니, 확실하지 않아도 됩니다.

### A — 업종 (재료: 배정받은 업종 10개)

업종마다 5개를 씁니다. **서로 다른 식으로** 씁니다. 아래는 예시일 뿐, 다섯 칸을 꼭 채워 넣을 필요는 없습니다.

| 방식 | 예: 업종 '보청기' |
|---|---|
| 그 업종을 부르는 말 | 보청기 / 보청기 가게 |
| 다른 말·더 넓은 말 | 청각 보조기 / 의료기기 |
| 구체적인 것 | 보청기 배터리 / 보청기 수리 |
| 말하듯 | 귀 잘 안 들릴 때 / 보청기 맞추는 곳 |

- 5개 중 2개 이상은 업종 이름이 들어가지 않게 씁니다.
- `~추천`, 지역 이름은 붙이지 않습니다. 지역은 D에서 다룹니다.
- 그 업종을 잘 모르면 아는 만큼만 써도 됩니다(3개도 괜찮음). 모르는 걸 지어내지 마세요.

### D — 지역 + 업종 (재료: 배정받은 시장 17곳)

그 시장 근처에 있거나 거기로 갈 계획인 나를 떠올리고, **지역 이름을 넣어** 검색합니다.

- 지역은 시장 이름, 동네, 역, 구 중 아는 것으로 씁니다(`망원시장 떡집`, `소래포구 꽃게`, `수원 순대`).
- 업종은 그 시장 `주요품목`에서 골라도 되고, 그 동네에서 찾을 법한 다른 것도 됩니다.
- 지역을 앞에 써도 뒤에 써도 됩니다(`떡집 망원시장`). 습관대로 씁니다.

## 자기 점검 (제출 전)

- [ ] AI·검색·지도를 보지 않았다
- [ ] 같은 말을 조금만 바꿔 여러 번 쓰지 않았다(`떡 파는 곳` / `떡 파는 데` / `떡 사는 곳` → 하나만)
- [ ] 일부러 넣은 오타가 없다
- [ ] D는 지역표현·가정위치ID를 채웠다
- [ ] 모든 줄에 의도를 적었다
