## 4. 검색어 해석

| # | 정책 | 상태 |
|---|---|---|
| 4-1 | 규칙으로 해석한다: 지명을 떼고 남은 말을 상호 / 브랜드 / 업종으로 나눈다("신촌 설렁탕" → 지역 신촌 + 업종) | [평가] |
| 4-2 | 같은 이름 지명: 검색 중심 30km 안 가장 가까운 곳, 없으면 대표적인 곳. 나머지는 "다른 ○○" 선택지 | [평가] |
| 4-3 | 검색어 전체가 검색 중심 10km 안 가게 이름이면 지역보다 그 가게를 먼저 | [평가] |
| 4-4 | 지명이 둘 이상이면 앞의 하나만 지역 | [평가] |
| 4-5 | 입력 정규화: 전각·반각 통일(NFKC), 앞뒤·연속 공백 정리. 최대 50자 | [팀] |
| 4-6 | 검색하지 않는 입력: 빈 값, 기호·이모지만, 일반어만('가게', '곳' 등) → "검색어를 입력해 주세요" | [팀] |
| 4-7 | 지명만 입력('신촌', '강남구')하면 검색하지 않고 지도를 그곳으로 옮긴다(8-2처럼 주변 가게 표시) | [팀] |
| 4-8 | 잘못 지명으로 읽히는 말('오케이 정형외과'의 '오케이')은 관리자가 **지명 제외 목록**에 넣는다 | [팀] |
| 4-9 | 부정·시간·시설·오타·초성·영어 업종어는 따로 처리하지 않는다 | [평가] |
| 4-10 | 검색어 해석은 **자바로 이식**한다(임베딩 장애 때도 동작해야 하므로) | [팀] |

## 5. 검색 범위와 반경 확장

| # | 정책 | 상태 |
|---|---|---|
| 5-1 | 지명 없음 → 검색 중심 1km | [팀] |
| 5-2 | 넓은 지명(시도·시군구·읍면) → 그 행정구역 안 | [팀] |
| 5-3 | 좁은 지명(동·역·시장) → 그 중심 1km | [팀] |
| 5-4 | 1km 안 관련 가게가 10곳 미만이면 10km까지 한 번에 넓힌다. 상호 검색도 같다 | [팀]·[평가] |
| 5-5 | 10km에도 없으면 "없음" | [팀] |
| 5-6 | 업종 칩을 고르면 칩을 범위 조건처럼 먼저 건다(10곳 세기도 칩 안에서) | [팀] |

## 6. 지도 모드

| # | 정책 | 상태 |
|---|---|---|
| 6-1 | 보이는 화면이 검색 범위다(반경 확장 없음). 화면 안 관련 가게 전부, 최대 300곳(넘으면 점수순) | [팀] |
| 6-2 | 지명·상호 때문에 결과가 화면 밖이면 **1위 가게를 중심으로 지도를 옮긴다**. 화면 안 결과가 0곳이면 화면 중심에서 1km → 10km로 찾아 있으면 옮긴다 | [팀] |
| 6-3 | 화면이 너무 넓으면(대각선 50km 초과) 검색하지 않고 확대 안내 | [팀] |
| 6-4 | 지도를 옮기면 '이 지역에서 다시 검색' 버튼(자동 검색 안 함) | [팀] |
| 6-5 | 겹치는 핀은 숫자로 묶는다(네이버 지도 마커 클러스터링). 묶는 픽셀 값 | [팀] / 값 [미정] 화면설계 |
| 6-6 | 목록 ↔ 지도 전환은 **같은 결과**를 보여 준다(다시 검색 안 함) | [팀] |

## 7. 순위와 노출

| # | 정책 | 상태 |
|---|---|---|
| 7-1 | 점수 = 의미 유사도 + 상호 일치 가산 + (업종 검색어면) 확장어 글자 점수. **거리는 점수에 넣지 않는다** | [평가] |
| 7-2 | 관련 확률이 기준(0.35) 이상인 가게만 보여 준다 | [평가] |
| 7-3 | 맨 위 가게: 브랜드 검색어의 범위 안 지점, 상호가 완전히 같은 가게(50km 안) → 항상 맨 위, 가까운 순. 맨 위 가게가 있으면 나머지는 확률 0.7 이상만 | [평가] |
| 7-4 | 넓힌 목록 순서: 맨 위 가게 → 1km 안 확실한 가게(확률 0.5 이상) → 나머지 점수순 | [팀]·[평가] |
| 7-5 | 같은 점수면 가게 ID 순(순서가 매번 같게) | [팀] |
| 7-6 | 업종 검색어는 맞는 가게가 없어도 1위가 하나 보일 수 있다. 보이는 가게가 모두 약하면 문구 ⑥으로 알린다 | [평가]·[팀] |

## 8. 화면: 칩·문구·목록·상세

| # | 정책 | 상태 |
|---|---|---|
| 8-1 | 업종 칩(17개)은 결과를 거르기만 하고 순위에는 쓰지 않는다 | [평가] |
| 8-2 | 검색어 없을 때: 처음엔 검색 중심 지도에 화면 안 가맹점 전부 표시, 칩만 누르면 그 업종만 표시, '조회'를 누르면 목록(가까운 순, 최대 300곳). 최근 검색어·검색 품질 통계에 넣지 않는다 | [팀] |
| 8-3 | 안내 문구: ① "1km 안에 없어 10km까지 찾았어요" ② "1km 안에 n곳, 10km까지 넓혀 m곳 더 찾았어요" ③ "10km 이내에 맞는 가게가 없어요" ④ "이 지역에 맞는 가게가 없어요"(지도) ⑤ "'○○'와 정확히 일치하는 가게는 없어요"(상호·브랜드 검색에 상호 일치 가게 없음) ⑥ "꼭 맞는 가게를 찾지 못해 비슷한 가게를 보여 드려요" ⑦ "대전 중구에서 찾았어요 · 다른 중구"(지역 해석 안내) ⑧ "이 화면에는 없어 가까운 곳을 보여 드려요" ⑨ "위치 정보가 없어 기본 위치 기준으로 찾았어요" ⑩ "지도를 확대하면 가게를 볼 수 있어요" ⑪ "검색어를 입력해 주세요" ⑫ "'○○' 업종에는 맞는 가게가 없어요 · 업종 해제" | 종류 [팀] / 최종 문구 [미정] 화면설계 |
| 8-4 | 목록: 한 페이지 20곳, 최대 300곳. 결과는 10분 보관해 다음 페이지가 겹치거나 빠지지 않게 | [팀] |
| 8-5 | 결과 카드: 상호, 업종, 거리, 시장명, 짧은 주소, 결제 수단, 즐겨찾기 | [팀] |
| 8-6 | 거리 표시: 1km 미만 `350m`, 이상 `1.2km`. 기준은 내 위치(GPS), GPS가 없으면 표시 안 함 | [팀] |
| 8-7 | 상세 화면: 디지털온누리 앱처럼 홈 / 메뉴 / 정보 탭. 지금은 **원천 데이터만** 보여 주고 없는 항목(이미지·영업시간·전화·메뉴·주차·QR)은 숨긴다 | [팀] |

## 10. 가맹점 데이터와 가게 상태

| # | 정책 | 상태 |
|---|---|---|
| 10-1 | 원천 항목: 가맹점명, 사업자번호, 가맹점번호, 주소, 위도·경도, 법정동코드, 시장유형, 시장명, 취급품목, 카드결제, 모바일결제 | [팀] |
| 10-2 | 가게 ID는 기존 ID를 그대로 쓰고 새 가게만 새로 발급. 같은 가게 판단 = 사업자번호 + 가맹점명 + 주소 | [팀] |
| 10-3 | 가게가 이전·상호 변경하면 새 가게로 처리되고, 관리자가 볼 수 있게 갱신 결과에 따로 표시 | [팀] |
| 10-4 | 원천 파일은 고치지 않는다. 품목이 없으면 비워 둔다. 좌표가 잘못된 가게는 검색에서 뺀다 | [팀] |
| 10-5 | 가게 상태: 영업중 / 확인 대기 / 폐업 / 관리자 숨김. 검색 대상 = 영업중이고 숨김이 아닌 가게 | [팀] |
| 10-6 | 주간 파일에서 사라지면 확인 대기(바로 검색에서 뺌) → 다음 주 다시 있으면 복구 → **2주 연속 없으면 폐업**. 기록은 지우지 않는다 | [팀] |
| 10-7 | 확인 대기·폐업 가게의 상세 화면은 상태 안내를 보여 준다 | [팀] |

## 11. 주간 가맹점 갱신

| # | 정책 | 상태 |
|---|---|---|
| 11-1 | 원천 데이터는 **주 1회** 갱신되고, 우리도 주 1회 반영한다(신규·변경·사라짐) | [팀] |
| 11-2 | 갱신 때 신규·변경 가게의 임베딩과 검색용 데이터(업종, 색인, 해석 사전, 확장어)를 다시 만든다 | [팀] |
| 11-3 | 너무 많은 가게가 한 번에 사라지면 멈추고 관리자 확인. 기준 % | 규칙 [팀] / 기준값 [대기] |
| 11-4 | 관리자가 실행하고 결과 건수를 본다. 동시에 두 번 돌지 않는다 | [팀] |
| 11-5 | 갱신 중에도 검색은 끊기지 않는다. 데이터 버전은 갱신 날짜(예: 2026-11-16)로 표시 | [팀] |
