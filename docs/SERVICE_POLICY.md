## 4. 검색어 해석

| # | 정책 | 상태 |
|---|---|---|
| 4-1 | 규칙으로 해석한다: 지명을 떼고 남은 말을 상호 / 브랜드 / 업종으로 나눈다("신촌 설렁탕" → 지역 신촌 + 업종) | [평가] |
| 4-2 | 같은 이름 지명: 검색 중심 30km 안 가장 가까운 곳, 없으면 대표적인 곳. 나머지는 "다른 ○○" 선택지 | [평가] |
| 4-3 | 검색어 전체가 검색 중심 10km 안 가게 이름이면 지역보다 그 가게를 먼저. 단 지명만 입력한 경우는 4-7이 우선 | [평가]·[팀] |
| 4-4 | 지명이 둘 이상이면 같은 곳을 가리키는 것끼리는 합치고("대전 중구"), 다른 곳이면 앞의 하나만 지역 | [평가] |
| 4-5 | 입력 정규화: 전각·반각 통일(NFKC), 앞뒤·연속 공백 정리. 최대 50자 | [팀] |
| 4-6 | 검색하지 않는 입력: 빈 값, 기호·이모지만, 일반어만('가게', '곳' 등) → "검색어를 입력해 주세요" | [팀] |
| 4-7 | 지명만 입력('신촌', '강남구')하면 검색하지 않고 지도를 그곳으로 옮긴다(8-2처럼 주변 가게 표시). 그 이름이 든 가게가 근처에 있으면('노량진' → '노량진수산…') 검색창 아래 작은 줄로 "'노량진수산' 가게 보기"를 보여 준다 | [팀] |
| 4-8 | 잘못 지명으로 읽히는 말('오케이 정형외과'의 '오케이')은 관리자가 **지명 제외 목록**에 넣는다 | [팀] |
| 4-9 | 부정·시간·시설·오타·초성·영어 업종어는 따로 처리하지 않는다 | [평가] |
| 4-10 | 검색어 해석은 **자바로 이식**한다(임베딩 장애 때도 동작해야 하므로) | [팀] |

## 5. 검색 범위와 반경 확장

| # | 정책 | 상태 |
|---|---|---|
| 5-1 | 지명 없음 → 검색 중심 1km | [팀] |
| 5-2 | 넓은 지명(시도·시군구·읍면) → 그 행정구역 안(반경 확장 없음) | [팀]·[평가] |
| 5-3 | 좁은 지명(동·역·시장) → 그 중심 1km | [팀] |
| 5-4 | 1km 안 관련 가게가 10곳 미만이면 10km까지 한 번에 넓힌다. 상호 검색도 같다 | [팀]·[평가] |
| 5-5 | 10km에도 없으면 "없음" | [팀] |
| 5-6 | 업종 칩·결제 칩은 점수·관련 확률을 전체 후보로 계산한 **뒤에** 거른다(평가한 확률을 그대로 쓰기 위해). 10곳 세기는 칩을 통과한 관련 가게로 | [팀] |

## 6. 지도 모드

| # | 정책 | 상태 |
|---|---|---|
| 6-1 | 보이는 화면이 검색 범위다(반경 확장 없음). 화면 안 관련 가게 전부, 최대 300곳(넘으면 점수순) | [팀] |
| 6-2 | 검색창으로 검색하면 **지도를 결과 상위 10곳에 맞춘다**(지명이 없으면 검색 중심도 포함, 줌은 1km 원 ~ 10km 원 사이, 넓은 지명은 대각선 50km까지). '현 지도 재검색'은 지도를 옮기지 않고, 화면 안 결과가 0곳이면 화면 중심에서 1km → 10km로 찾아 있으면 옮긴다 | [팀] |
| 6-3 | 화면이 너무 넓으면(대각선 50km 초과) 검색하지 않고 확대 안내 | [팀] |
| 6-4 | 지도를 옮기면 '현 지도 재검색' 버튼(온누리 앱 모양·라벨, 옮기기 전에는 숨김, 자동 검색 안 함) | [팀] |
| 6-5 | 겹치는 핀은 숫자로 묶는다(네이버 지도 마커 클러스터링). 묶는 픽셀 값 | [팀] / 값 [미정] 화면설계 |
| 6-6 | 목록 ↔ 지도 전환은 **같은 결과**를 보여 준다(다시 검색 안 함). 검색창으로 검색하면 항상 목록 규칙(반경 1km → 10km)으로 찾고 지도 핀과 하단 시트(닫힘 / 중간 / 전체 = 목록)로 함께 보여 준다. 지도 규칙(6-1)은 '현 지도 재검색'에만 쓴다 | [팀] |

## 7. 순위와 노출

| # | 정책 | 상태 |
|---|---|---|
| 7-1 | 점수 = 의미 유사도 + 상호 일치 가산 + (업종 검색어면) 확장어 글자 점수. **거리는 점수에 넣지 않는다** | [평가] |
| 7-2 | 관련 확률이 기준(0.35) 이상인 가게만 보여 준다 | [평가] |
| 7-3 | 맨 위 가게: 브랜드 검색어의 범위 안 지점, 상호가 완전히 같은 가게(50km 안) → 항상 맨 위, 가까운 순. 맨 위 가게가 있으면 나머지는 확률 0.7 이상만 | [평가] |
| 7-4 | 넓힌 목록 순서: 맨 위 가게 → 1km 안 확실한 가게(확률 0.5 이상) → 나머지 점수순 | [팀]·[평가] |
| 7-5 | 같은 점수면 가게 ID 순(순서가 매번 같게) | [팀] |
| 7-6 | 업종 검색어는 맞는 가게가 없어도 1위가 하나 보일 수 있다. 보이는 가게가 모두 약하면 문구 ⑥으로 알린다 | [평가]·[팀] |

## 8. 화면: 칩·문구·목록·상세

| # | 정책 | 상태 |
|---|---|---|
| 8-1 | 업종 칩(17개)은 결과를 거르기만 하고 순위에는 쓰지 않는다 | [평가] |
| 8-1a | **결제 칩**(업종 칩 바로 옆): 전체 / QR결제 / 카드결제 / 바코드결제, **여러 개 선택**(카드·QR이 함께 되는 가게가 많음). 고른 수단 중 하나라도 되는 가게(OR), 전부 또는 하나도 안 고르면 전체. 업종 칩과 함께 쓰면 둘 다 맞는 가게만. 거르기만 하고 순위에 쓰지 않는다. 원천 '모바일결제' = QR결제. 결제 여부가 비어 있는 가게는 해당 칩에서 빠진다 | [팀] |
| 8-1b | 바코드결제는 원천에 데이터가 없어 데이터가 생길 때까지 칩을 보이지 않는다(구조만 만든다) | [팀] / 데이터 [대기] |
| 8-2 | 검색어 없을 때: 처음엔 검색 중심 지도에 화면 안 가맹점 전부 표시, 칩만 누르면 그 업종·결제 수단 가게만 표시, 같은 가게를 하단 시트에 목록으로(가까운 순, 최대 300곳, 별도 '조회' 버튼 없음). 0곳이면 ④. 최근 검색어·검색 품질 통계에 넣지 않는다 | [팀] |
| 8-3 | 안내 문구: ① "1km 안에 없어 10km까지 찾았어요" ② "1km 안에 n곳, 10km까지 넓혀 m곳 더 찾았어요" ③ "10km 이내에 맞는 가게가 없어요" ③-2 "대전 중구에 맞는 가게가 없어요"(넓은 지명 0곳) ④ "이 지역에 맞는 가게가 없어요"(지도) ⑤ "'○○'와 정확히 일치하는 가게는 없어요"(상호·브랜드 검색에 상호 일치 가게 없음) ⑥ "꼭 맞는 가게를 찾지 못해 비슷한 가게를 보여 드려요" ⑦ "대전 중구에서 찾았어요 · 다른 중구"(지역 해석 안내) ⑧ "이 화면에는 없어 가까운 곳을 보여 드려요" ⑨ "위치 정보가 없어 기본 위치 기준으로 찾았어요" ⑩ "지도를 확대하면 가게를 볼 수 있어요" ⑪ "검색어를 입력해 주세요" ⑫ "선택한 조건(업종·결제)에 맞는 가게가 없어요 · 조건 해제". 큰 문구는 하단 시트 맨 위, 작은 줄(⑦·⑨)은 검색창 아래 띠, ⑩만 토스트 | 종류·위치 [팀] / 최종 문구 [미정] 화면설계 |
| 8-4 | 목록: 한 페이지 20곳, 최대 300곳. 결과는 캐시에 10분 보관해(DB 아님) 다음 페이지가 겹치거나 빠지지 않게 | [팀] |
| 8-5 | 결과 카드: 상호, 업종, 시장명·시장유형, 짧은 주소, 거리, 결제 수단 글자("QR결제 \| 카드결제"), 즐겨찾기. 취급품목·전화는 넣지 않는다 | [팀] |
| 8-6 | 거리 표시: 1km 미만 `350m`, 이상 `1.2km`. 기준은 내 위치(GPS), GPS가 없으면 표시 안 함. 로그의 거리는 검색 중심 기준(정렬·반경과 같은 기준) | [팀] |
| 8-7 | 상세 화면: 디지털온누리 앱 상세 배치를 따르되 **탭 없이 홈 한 화면**. 업종·시장명·시장유형, 상호, 주소, 거리, 결제 수단 + 즐겨찾기·공유·길찾기. 없는 항목(이미지·영업시간·전화·메뉴·주차·QR·상품권 태그)과 취급품목은 넣지 않는다 | [팀] |

## 9. 회원 기능

| # | 정책 | 상태 |

| 9-4 | 탈퇴하면 회원 정보·최근 검색어·즐겨찾기 삭제. 분석 로그는 회원과 연결되지 않으므로 그대로 | [팀] |

## 10. 가맹점 데이터와 가게 상태

| # | 정책 | 상태 |
|---|---|---|
| 10-1 | 원천 항목: 가맹점명, 사업자번호, 가맹점번호, 주소, 위도·경도, 법정동코드, 시장유형, 시장명, 취급품목, 카드결제, 모바일결제(화면 이름은 QR결제) | [팀] |
| 10-2 | 가게 ID는 기존 ID를 그대로 쓰고 새 가게만 새로 발급. 같은 가게 판단 = 사업자번호 + 가맹점명 + 주소 | [팀] |
| 10-3 | 가게가 이전·상호 변경하면 새 가게로 처리되고, 관리자가 볼 수 있게 갱신 결과에 따로 표시 | [팀] |
| 10-4 | 원천 파일은 고치지 않는다. 품목이 없으면 비워 둔다. 좌표가 잘못된 가게(0 좌표·국내 밖·충돌)는 갱신을 멈추지 않고 그 가게만 '좌표 오류'로 표시해 검색에서 뺀다. 관리자가 좌표를 고치면 검색에 들어간다 | [팀] |
| 10-5 | 가게 상태: 영업중 / 확인 대기 / 폐업 / 관리자 숨김. 검색 대상 = 영업중이고 숨김이 아니며 좌표 오류가 아닌 가게 | [팀] |
| 10-6 | 주간 파일에서 사라지면 확인 대기(바로 검색에서 뺌) → 다음 주 다시 있으면 복구 → **2주 연속 없으면 폐업**. 기록은 지우지 않는다 | [팀] |
| 10-7 | 상세 화면에 상태 안내는 없다. 확인 대기 가게는 평소처럼 보여 주고, 폐업·숨김 가게는 '찾을 수 없음' 화면 | [팀] |

## 11. 주간 가맹점 갱신

| # | 정책 | 상태 |
|---|---|---|
| 11-1 | 원천 데이터는 **주 1회** 갱신되고, 우리도 주 1회 반영한다(신규·변경·사라짐) | [팀] |
| 11-2 | 갱신 때 신규·변경 가게의 임베딩과 검색용 데이터(업종, 색인, 해석 사전, 확장어)를 다시 만든다 | [팀] |
| 11-3 | 너무 많은 가게가 한 번에 사라지면 멈추고 관리자 확인. 기준 % | 규칙 [팀] / 기준값 [대기] |
| 11-4 | 관리자가 실행하고 결과 건수를 본다. 동시에 두 번 돌지 않는다 | [팀] |
| 11-5 | 갱신 중에도 검색은 끊기지 않는다. 데이터 버전은 갱신 날짜 + 순번(예: `2026-11-16`, 같은 날 다시 하면 `2026-11-16.2`) | [팀] |
