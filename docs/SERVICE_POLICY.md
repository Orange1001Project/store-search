## 5. 검색 범위와 반경 확장

| # | 정책 | 상태 |
|---|---|---|
| 5-1 | 지명 없음 → 검색 중심 **1km**(`radius.first_km`) | [팀] |
| 5-2 | 넓은 지명(시도·시군구·읍면) → **법정동 코드 앞자리**로 거른다(앞 2·5·8자리) | [팀] |
| 5-3 | 좁은 지명(동·행정동·역·시장) → 그 중심 1km | [팀] |
| 5-4 | 1km 안 관련 가게(7절)가 **10개 미만**이면 **10km**까지 한 번에 넓힌다(`radius.expand_if_relevant_below`, `radius.max_km`). 중간 단계는 없다 | [팀]·[평가] |
| 5-5 | 상호 검색도 같은 규칙으로 넓힌다(1km에서 멈추는 예외 없음) | [평가] |
| 5-6 | 10km에도 없으면 더 넓히지 않고 "없음" 문구(8절) | [팀] |
| 5-7 | 지도 모드는 반경 대신 화면 사각형(6절) | [팀] |

## 7. 후보·점수·노출 판단·정렬

| # | 정책 | 상태 |
|---|---|---|
| 7-1 | 후보 = 범위 안 **임베딩 상위 50 ∪ 글자 BM25 상위 50**. 업종 검색어는 LLM 확장어 BM25 **상위 200**을 더한다 | [평가] |
| 7-2 | 범위 안 후보 전부와 **정확히** 유사도를 계산한다(근사 검색 색인 없음) | [평가] |
| 7-3 | 점수 = 후보 안에서 0~1로 맞춘(min-max) 임베딩 유사도 + **0.5 × 상호 일치**(별칭 포함) + 업종 검색어면 **0.3 × 확장 BM25 ÷ 최댓값**(`ranking.expansion_w`). **거리는 점수에 넣지 않는다** | [평가] |
| 7-4 | 글자 BM25로만 들어온 후보는 임베딩 점수 0(정규화 최솟값). 단 상호·브랜드 검색어의 상호 일치 후보에는 실제 코사인을 붙인다(`ranking.real_cosine: name`) | [평가] |
| 7-5 | 임베딩 쿼리는 지명을 포함한 **검색어 전체**, BM25 쿼리는 지명·서술어·지점 접미사를 뺀 단어 | [평가] |
| 7-6 | BM25: 전국 21만 곳 색인 하나, 글자 2~3조각, k1 1.5, b 0.75, 음수 idf 0. **애플리케이션 메모리에서 계산**하고 `pg_trgm`·`ts_rank`로 대신하지 않는다(점수가 달라져 관련 확률 계수와 어긋남) | [평가]·[팀] |
| 7-7 | **맨 위 가게**: 브랜드 지점(`ranking.brand_sort: distance`)과 상호 완전 일치(`ranking.exact_name_first`, 검색 중심 50km 안)는 점수 = 100 − 거리km로 항상 맨 위, 가까운 순 | [평가] |
| 7-8 | **노출 판단**: 관련 확률(로지스틱 식, 계수 파일 `results/service_pipeline/x1/calibrator.json`) **≥ 0.35**만 보여 준다(`relevance.threshold_p`). 특성은 그 단계 후보 안에서 계산하고, 맨 위 가게는 계산에서 빼고 항상 관련 | [평가] |
| 7-9 | 목록에 맨 위 가게가 하나라도 있으면 나머지는 **≥ 0.7**만(`ranking.brand_others_min_p`) | [평가] |
| 7-10 | 확장 목록 순서: 맨 위 가게(거리순) → 1km 안 확률 **≥ 0.5**(`ranking.tier_min_p`) → 나머지(1km 약한 가게 + 10km) 점수순 | [팀]·[평가] |
| 7-11 | 동점 규칙 없음. "점수 차 0.01 이내면 가까운 순"은 넣지 않는다(평가에 없음) | [평가] |
| 7-12 | 알려진 동작: 업종 검색어의 1위는 맞는 가게가 없어도 하나는 보인다(정규화의 대가) | [평가] |
| 7-13 | 옮길 때 그대로 지킬 동작 11개: `docs/BACKEND_HANDOFF.md` 1-1 | [평가] |

| 8-7 | 결과 카드·상세 화면에 보일 정보(상호, 업종, 거리, 주소, 품목, 카드·모바일결제, 시장명 등), 거리 표시 형식 | [미정] |

## 9. 회원 기능

| 9-6 | **즐겨찾기**: 회원–가게 추가·해제, 같은 가게는 한 번만 | [팀] |
| 9-7 | 가게가 **폐업 확정** 또는 **관리자 숨김**이 되면 즐겨찾기를 자동 삭제한다 | [팀] |
| 9-8 | 가게가 **확인 대기**(10-3) 중에는 지우지 않고 목록에서만 숨긴다. 가게가 돌아오면 그대로 보인다 | [팀] |
| 9-9 | **탈퇴**: 회원·로그인 수단·최근 검색어·즐겨찾기를 삭제한다. 분석 로그는 원래 회원과 연결되지 않으므로 그대로 둔다 | [팀] |

### 폴백(임베딩 장애 때 검색) — 2026-11-10 팀 결정

정상 검색의 노출 판단(관련 확률 ≥ 0.35)은 임베딩 점수가 있어야 계산되므로 폴백 때는 쓸 수 없다. 그래서 폴백은 **확률 대신
"검색어 낱말이 가게에 실제로 들어 있는가"로 거르는 일반 키워드 검색**으로 동작한다. 장애 동안 품질은 낮아져도 결과는 계속 주는
**단계적 기능 저하**(graceful degradation)와, 장애가 난 서버를 계속 두드리지 않고 끊었다가 주기적으로 다시 확인하는 **회로 차단기**(circuit breaker)는
검색 서비스가 흔히 쓰는 방식이다(Google SRE Book "Addressing Cascading Failures", Nygard *Release It!*). 폴백은 평가하지 않은 동작이라
장애 때만 쓰고, 품질 통계에서 뺀다.

|---|---|---|
| 17-11 | **전환 조건**: 임베딩 호출이 시간 초과·오류이면 그 검색은 폴백으로 처리한다. 짧은 시간에 실패가 이어지면 회로 차단기를 열어 임베딩 호출을 잠시 멈추고, 주기적으로 한 번씩 다시 시도해 성공하면 정상으로 돌아온다. 시간 초과 값·실패 횟수·재시도 간격 | 방식 [팀] / 값 [미정] (추천: 시간 초과 150ms — p95 300ms 예산의 절반) |
| 17-12 | **바뀌지 않는 것**: 검색 중심(3절), 검색어 해석(4절), 검색 범위·1km → 10km 확장 규칙(5절), 지도 범위·상한 300(6절), 업종 칩(8-1), 맨 위 가게(브랜드 지점·상호 완전 일치는 임베딩이 필요 없으므로 7-7 그대로) | [팀] |
| 17-13 | **후보**: 범위 안 글자 BM25 상위 50 + 상호 일치 가게. 업종 검색어는 LLM 확장어 BM25 상위 200도 더한다(확장어는 캐시라 임베딩 없이 쓸 수 있다) | [팀] |
| 17-14 | **노출 판단(관련 확률 대신)**: 맨 위 가게가 아닌 가게는 **검색어 핵심 낱말**(지명·서술어·지점 접미사를 뺀 말, 7-5의 BM25 쿼리와 같음) **하나 이상이 상호 또는 취급품목에 그대로 들어 있을 때만** 보여 준다. 업종 검색어는 확장어가 들어 있어도 된다("고기 파는 곳" → 확장어 '정육'이 품목에 있는 가게). 맨 위 가게가 있으면 나머지는 핵심 낱말이 **상호**에 들어 있는 가게만(7-9의 0.7 대신) | [팀] |
| 17-15 | **정렬**: 맨 위 가게(거리순) → 나머지는 BM25 점수순(확장어 점수 포함, 7-3과 같은 0.3 가중). 1km 먼저 순서(7-10)는 확률이 없으므로 "1km 안 노출 가게 → 10km 노출 가게" 순으로 대신한다 | [팀] |
| 17-16 | **반경 확장 기준**: 17-14를 통과한 1km 가게가 10개 미만이면 10km까지(5-4와 같은 숫자) | [팀] |
| 17-17 | **화면**: 사용자에게 장애 안내를 따로 띄우지 않는다. 문구는 정상 때와 같다(8-3). 폴백 결과는 검색 결과 캐시에 저장하지 않는다(복구 뒤 낮은 품질 결과가 계속 나가지 않게) | [팀] |
| 17-18 | **기록·감시**: 로그 `fallback = true`(14-4). 폴백 검색은 관리자 품질 통계(결과 없음·클릭률 등, 14-9)에서 빼고 "폴백 비율"로 따로 본다. 폴백 비율이 기준을 넘으면 알람(14-10) | [팀] / 알람 기준 [미정] |
