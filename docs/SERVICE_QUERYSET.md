# 서비스형 쿼리셋 v1 (2026-10-19)

기존 벤치마크(업종 의도 72개, 548개 쿼리)는 업종명을 보고 쓴 쿼리라 실제 사용자 쿼리의 큰 부분을 재지 못한다
(`docs/SERVICE_READINESS.md` 1절). 그래서 쿼리 종류를 넓힌 별도 셋을 만든다. 기존 val/test와 섞지 않는다.

## 1. 무엇을 몇 개

| 묶음 | 목표 | 내용 | 작성 재료(템플릿 시트) |
|---|---|---|---|
| A 업종 확장 | 150 | 기존 셋에 없는 업종·품목(태권도, 보청기, 마라탕, 식육…)과 질의 1~2개뿐인 기존 업종 | `A_업종후보` |
| B 상호명·브랜드 | 100 | 체인(GS25↔지에스25, BBQ↔비비큐), 개별 상호의 전체·일부·지점명 | `B_가맹점표본`, `B_체인목록` |
| C 상품·상황 | 80 | 업종명 없이 상황만 보고 쓴 쿼리 | `C_상황카드` |
| D 지역+업종 | 50 | "망원시장 떡집", "강남 치킨" | `D_시장표본` |
| E 결과 없음 | 20 | 가맹점이 아닐 법한 대상(코스트코, 영화관) | `E_결과없음후보` |

오타는 넣지 않는다(철자 교정은 앞단 처리 — `configs/benchmark/inactive_queries_v1.yaml` 머리말).

**개수 근거**: bad@3 ≤ 0.05를 판별하려면 실제 값이 0.03일 때 평가용 약 300개가 필요하다. nDCG Δ 0.01을 구분하려면 약 500개가 필요하다
(final_v1_val 비교의 쿼리별 차이 표준편차 약 0.08에서 추정). 1차 400개 중 약 300개를 평가용, 약 100개를 개발용으로 둔다.
검색 로그를 확보하면 2차로 로그에서 빈도 구간별로 층화 추출해 500개를 더한다.

## 2. 작성 원칙

1. **각자 따로 쓴다.** 5명 이상, 팀 밖 사람을 포함한다. 서로의 쿼리를 보지 않는다.
2. **C는 카드만 보고 쓴다.** 업종 목록·코퍼스를 보면 그 단어를 베낀다. 기존 셋이 T1·T2에 쏠린 원인이 이것이다.
3. **B는 가맹점에서 거꾸로 쓴다.** 표본 가맹점을 보고 "이 가게를 찾는다면 뭐라고 칠까"를 쓴다. 표본의 25%는 취급품목이 비었거나
   "음식점"뿐인 가맹점이다. 이런 가맹점은 상호명으로만 찾을 수 있다.
4. **LLM은 후보로만 쓴다.** 작성방식=LLM후보로 표시하고, test에는 직접 쓴 쿼리 중심으로 넣는다.
5. **모든 쿼리에 가정위치를 붙인다.** B는 표본 가맹점 위치, D는 시장(M번호)을 쓴다. A·C·E는 비우면 나중에 자동 배정한다.
   위치 기능을 지금 만들지 않아도, 쿼리셋을 나중에 다시 만들지 않도록 위치 맥락을 지금 기록한다.

## 3. 판정과 집계

- 사람은 업종·상호 관련성만 판정한다. 지역 일치는 주소·좌표로 자동 계산한다.
- pool은 상위 20개 × 3~4개 시스템이다(bge-m3 mj, BM25, 하이브리드, zero-shot). 쿼리당 약 45개가 된다.
  A·B 이중 판정은 20%에만 하고(일치도 확인용), 나머지는 1인 판정 + AI 초안으로 한다(AI 초안은 판정자 한 명만 본다 — EVALUATION_POLICY 1절).
- **가이드라인 추가가 필요하다(판정 전에)**: 상호명 쿼리("교촌" → 모든 지점? 가까운 지점?)의 등급과, E 묶음의 판정 기준.
- 묶음별로 따로 보고한다. D는 위치 기능이 없는 지금은 기준점으로만 쓰고, 주 지표에 섞지 않는다.
- split: A의 새 업종은 family 단위로 나누고, B~E는 쿼리 단위로 나눈다.

## 4. 실행

```bash
python scripts/make_service_queryset_template.py            # data/query/service_queryset_v1.xlsx 생성(있으면 안 덮어씀)
python scripts/make_service_queryset_template.py --dry-run  # 시트별 행 수만 확인
```

설정(목표 개수, 상황 카드, 브랜드 별칭, seed)은 `configs/query/service_queryset_v1.yaml`에 있다. 템플릿을 배포한 뒤에는
seed를 바꾸지 않는다. 바꾸면 표본ID(S·M번호)가 다른 가맹점을 가리키게 된다.
작성이 끝난 xlsx를 쿼리셋으로 가져오는 스크립트(queries·가정위치 자동 배정)는 작성이 끝난 뒤에 만든다.
