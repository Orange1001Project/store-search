## 1. 개요

### 1-1. 목적·범위

- 전국 전통시장·골목형상점가 가맹점(약 21만 곳)을 자연어로 찾는 지도 기반 검색 서비스를 만든다.
- 1차: **반응형 웹**(모바일 우선) + 관리자 웹. 앱은 이후(같은 API를 쓴다).
- 범위 밖: 오타 교정, 재정렬 모델, 실시간 LLM, 리뷰·평점, 개인화, 원천에 없는 상세 데이터(이미지·영업시간·전화·메뉴·주차·QR), 결제.

### 1-2. 사용자

| 사용자 | 할 수 있는 일 |
|---|---|
| 비회원 | 검색, 지도·목록, 가게 상세, 길찾기·공유 |
| 회원 | 비회원 기능 + 최근 검색어, 즐겨찾기, 탈퇴 |
| 관리자 | 화면: 가맹점 조회·수정·숨김, 통계. 운영자(DB·서버 스크립트): 주간 갱신, 참조 데이터·원천 변경 확인, 주소·좌표 수정, 관리자 계정 관리(v0.10) |

### 1-3. 시스템 구성

| 구성 요소 | 역할 | 기술 |
|---|---|---|
| 웹 화면 | 사용자 웹(반응형), 관리자 웹 | React, 네이버 지도 JavaScript API v3 |
| API 서버 | 검색(해석·후보·점수·노출·정렬), 회원, 관리자, 로그 수집 | Spring Boot + JPA |
| 임베딩 추론 서버 | 검색어 문장 → 1024차원 벡터, 주간 갱신 때 가게 벡터 생성 | 별도 서버(bge-m3 미세조정 v1, fp32) |
| DB | 가맹점·벡터·참조 데이터·회원·로그 | PostgreSQL 16 + PostGIS 3.4 + pgvector 0.8 이상 |
| 배치 | 주간 갱신, 확장어 생성, 로그 집계·삭제, 즐겨찾기 정리 | API 서버 내 스케줄러 또는 별도 작업 ⚠(서버 구성 대기) |
| 외부 연동 | 지도, 소셜 로그인 | 네이버 지도(NAVER Cloud Platform Maps), 카카오 로그인, 구글 로그인 |

### 1-4. 출시 우선순위

기능이 많아 1차 출시에 꼭 필요한 것부터 만든다. 각 요구사항의 '우선' 칸과 7절 화면 표의 '우선' 칸이 이 기준을 따른다(v0.8).

| 단계 | 화면 | 기능 묶음 |
|---|---|---|
| **P0** 출시 핵심 | U-01 메인, U-03 목록, U-04 지도, U-05 요약 카드, U-06 상세, U-11 찾을 수 없음, U-12 위치 정보 이용 안내, E-01 화면을 불러오지 못함 · A-01 로그인, A-03 가맹점 목록, A-04 상세·수정(주소·좌표 제외) | 검색어 해석, 검색 중심·1km→10km 확장, 후보·점수·노출·정렬(평가한 동작 그대로), 업종·결제 칩, 안내 문구, 목록 20곳씩, 지도 핀·현 지도 재검색·겹친 가게 목록, 상세·길찾기, 관리자 로그인·첫 로그인 비밀번호 변경(첫 계정은 배포 스크립트), 가맹점 수정·숨김, 주간 갱신(서버에서 스크립트로 실행)·무중단 버전 전환, 검색 로그, 폴백 검색, 비기능 요구사항 전체 |
| **P1** 1차 목표 | U-02 최근 검색어, U-07 로그인, U-08 가입 동의, U-09 내 정보, U-10 관심 가맹점 · A-10 통계 | 회원(소셜 로그인·약관·최근 검색어·즐겨찾기·닉네임 변경·탈퇴), 지명만 입력·같은 이름 지명·지명 둘 이상, 확대 안내·핀 묶음·다른 지역 선택, 공유, 갱신 미리보기·안전장치·후처리(스크립트 결과로 확인), 원천 변경·별칭·지명 제외·관리자 계정 관리(DB·스크립트로 직접), 행동 이벤트·노출 측정·봇 표시, 통계(CSV는 화면에서 만듦), 회로 차단기 |
| **P2** 출시 뒤 | A-02 관리자 홈, A-05 주간 갱신, A-06 원천 변경 알림, A-07 브랜드 별칭, A-08 지명 제외, A-09 해석 미리보기, A-12 관리자 계정, A-04의 주소·좌표 수정 | 자동완성, 로그인 수단 추가, 체류 측정, 지명 사전·업종 교체 화면, 확장어 주간 생성(처음엔 만들어 둔 캐시 사용) |

- **회원 기능은 1차 출시에 넣는다(2026-11-13 결정).** P1이지만 출시 범위 안이다.
- P1 묶음 안의 지명 처리(FR-SRC-04·06·08)는 평가한 검색 동작이라 이식은 P0의 해석 코드와 함께 한다. 화면 표시(선택지 줄)만 P1이다.
- 지명 제외 목록·브랜드 별칭 데이터는 검색이 쓰므로 P0에 기본 데이터로 들어간다. 관리 화면(A-07·A-08)은 P2이고, 1차는 DB 표에 직접 넣는다.
- **관리자 화면은 가맹점 조회·수정(A-03·A-04)과 통계(A-10)만 둔다(2026-11-13 결정).** DB에서 조회·수정할 수 있는 일(별칭·지명 제외·원천 변경 확인·관리자 계정·주소·좌표)과 주간 갱신은 화면 없이 DB 직접 작업·서버 스크립트로 하고, 그 화면은 P2로 미룬다. 기능 규칙(사유 필수, 1분 안 반영, 무중단 전환 등)은 그대로다.

## 7. 화면 목록·흐름

화면설계의 입력이다. 화면 ID는 화면설계 단계에서 그대로 쓴다. 완성된 화면 그림은 [`docs/design/README.md`](design/README.md)(원본: claude.ai 디자인 캔버스). 모바일 기준이며, 데스크톱(가로 1024px 이상)은 U-03·U-04를 한 화면에 함께 둔다(FR-MAP-09, 화면설계는 모바일 다음에).

**공통 틀(모바일)**: 디지털온누리 앱 '가맹점 찾기' 디자인. 상단 헤더('가맹점 찾기 ×')는 두지 않고 **검색창이 항상 맨 위**, 검색창 오른쪽에 메뉴(☰). 메뉴: 비회원은 로그인 안내("로그인하면 관심 가맹점과 최근 검색어를 저장할 수 있어요" · 로그인) + 관심 가맹점 >, 회원은 "{닉네임}님, 반가워요!" + 내 정보 > + 관심 가맹점 >. 둘 다 아래쪽에 이용약관 · 개인정보처리방침 링크(FR-MBR-13). 그 아래 업종 칩·결제 칩, 지도, 지도 위 내 위치 버튼·'현 지도 재검색', 하단 3단계 시트(닫힘 / 중간 / 전체). 직접 검색·내주변·관심 가맹점 탭과 시장·지역 검색 구분은 두지 않는다. U-03·U-04는 이 틀에서 시트 상태만 다르다.

## 8. 오류·로딩 상태

안내 문구(FR-MSG-02)는 "결과가 없을 때"만 다룬다. 아래는 그 밖의 상태다. 보통 서비스처럼 **아무것도 못 보여 줄 때만 전체 화면, 쓰던 중이면 대화상자(이전 화면 유지), 가벼운 알림은 토스트**로 나눈다(2026-11-16). 대화상자는 제목 한 줄 + 설명 + 버튼 1~2개(보조 버튼 왼쪽, 주 버튼 오른쪽 주황), 바깥을 눌러도 닫히지 않는다. 그림은 `docs/design/`(E-01, 대화상자 모음).
