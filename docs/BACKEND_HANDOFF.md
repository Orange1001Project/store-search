## 2. 그대로 옮겨야 하는 동작

평가 수치가 이 동작으로 나왔다. 하나라도 바꾸면 다시 판정·평가해야 한다.

| # | 동작 | 바꾸면 |
|---|---|---|
| 1 | 임베딩 점수는 **그 단계 후보 안 min-max** 정규화(1위 = 1) | 코사인 절대값은 쿼리마다 크기가 달라 관련 확률이 무너진다 |
| 2 | **글자 BM25로만 들어온 후보는 임베딩 점수 0**. 실제 코사인은 상호·브랜드 검색어의 상호 일치 후보에만 | 모든 후보에 붙이면 10km 목록 nDCG 0.828 → 0.804 |
| 3 | 임베딩 쿼리 = **검색어 전체(지명 포함)**, BM25 쿼리 = 지명·서술어·지점 접미사를 뺀 단어 | 지명을 빼면 dev 좁은 지역 nDCG −0.060 |
| 4 | 관련 확률 특성은 **그 단계 후보 집합 안**에서 계산(1km 단계 = 1km 후보로 다시 계산) | 계수가 그렇게 학습됨 |
| 5 | **맨 위 가게**(브랜드 지점·상호 완전 일치, 점수 = 100 − 거리km)가 목록에 하나라도 있으면 나머지는 P ≥ 0.7. 맨 위 가게는 확률 특성 계산에서 뺀다. 의도가 아니라 목록 기준 | 평가한 동작이 이것 |
| 6 | 상호 완전 일치는 검색 중심 50km 안만 | 점수가 50 아래로 내려가 일반 후보와 섞인다 |
| 7 | 확장 목록 순서 = 맨 위 가게(거리순) → 1km 안 P ≥ 0.5 → 나머지 점수순 | 팀 결정 + 평가 |
| 8 | 모든 거리 규칙의 기준점은 **검색 중심**. GPS를 따로 넣지 않는다 | 평가 좌표가 검색 중심 하나 |
| 9 | BM25 = **전국 색인 하나**, 글자 2–3gram, k1 1.5, b 0.75, 음수 idf 0, **애플리케이션 메모리 계산**(`pg_trgm`·`ts_rank` 금지) | 식이 달라지면 `bm25_rel` 특성이 계수와 어긋난다 |
| 10 | 동점 규칙 없음(1단계 순서) | 평가 안 한 규칙 |
| 11 | 확장어 캐시 키 = 정규화한 전체 검색어(NFKC → 앞뒤 공백 제거 → 연속 공백 하나 → 영문 소문자). 캐시에 없으면 확장 없이 | 평가 요청 756개 모두 이 키와 같았다 |
| 12 | 지점 접미사 목록은 파일(DB)로 고정해 쓰고 가맹점 갱신 때만 다시 만든다 | 매번 계산하면 갱신마다 달라진다 |

## 4. 해 봤지만 쓰지 않는 것

reranker(bge-reranker-v2-m3), 업종 가산점, 모든 후보에 실제 코사인, 관련 확률 식 바꾸기(가게 텍스트 특성·적용 분포 재학습·정규화 전 코사인),
임베딩 쿼리에서 지명 빼기, LLM 가게 텍스트 보강 — 모두 정책 지표가 나빠지거나 효과가 없었다(실험 기록 1-5, 11-15 ~ 11-27).

## 5. 알려진 한계

- DB에 없는 가게 이름 검색은 비슷한 업종 가게가 나온다 → "정확히 일치하는 가게는 없어요" 문구(정책 8-4).
- 품목이 '음식'·'한식'뿐인 가게가 많아 상황형 검색어(복날 음식, 도시락)가 약하다.
- 동음·글자 겹침('시계 배터리' → 자동차 배터리).
- 업종 검색어 1위는 맞는 가게가 없어도 하나는 보인다(정규화의 대가, 동작 1).
- 검색어 해석이 '오케이 정형외과'를 지명 '오케이' + 업종으로 읽는다(지명 사전 정리 후보).
- 폴백(임베딩 장애) 동작은 평가하지 않았다(정책 17-11 ~ 17-18).
